# 🔒 有料記事モード(`tier=entry` / `tier=premium`) — 追加要件

以下は **base prompt(article_system.md)に加えて適用される** 追加ルールです。
無料記事より「**お金を払う価値**」がはっきり伝わる差別化要素を必ず入れます。

## 共通(entry / premium 両方)
- タイトル先頭の `【保存版】` を **`【有料解説】`** または **`【プロ視点】`** に変更
- 冒頭に **「本記事の有料部分でわかること」** ボックス(3-5 項目)を明示
- 本文の **3 割程度を無料閲覧部分(プレビュー)** として書き、それ以降は有料部分扱い
  - note の `<!-- ここから有料 -->` マーカーを最適な位置に明示する
  - 無料部分の末尾を「**ここから先は具体的な数値・戦略を解説します**」で締める

## entry(¥100 — 集客記事)
- ターゲット: 「軽く有料記事を試したい初心者」
- ボリューム: **本文 6,000〜8,000 字**(無料記事より少し短く、密度高く)
- 有料部分の核心:
  - **1 つの "今日明日使えるアクション"** を具体的な数値で
  - **5 ステップ程度のシンプルなフレームワーク** を表で
  - 過剰に深掘りせず、 ¥100 でちょうど納得感のある量

## premium(¥500 — 主力記事)
- ターゲット: 「真剣に投資判断したい中級者」
- ボリューム: **本文 12,000〜15,000 字**(無料 10,000 字より分厚く)
- 有料部分の核心:
  - **独自データ・独自視点**(本来は限界があるが「過去 3 回の同様局面のパフォーマンス比較」等の分析的構造で)
  - **3 つ以上のシナリオ別アクション** を表で
  - **失敗事例 / 成功事例** のミニケーススタディ 2 件
  - 末尾に **チェックリスト(印刷推奨)** を付ける

## 価格を支える構造ライティングの鉄則
- 「**有料部分の冒頭 3 行で "もう元取った" と思わせる**」 → 返金リクエスト防止
- 「**読み返したくなる構造**」 → 表・チェックリスト・図解(Markdown 風)を多用
- 「**実名業者・実値数字** を匂わせず、汎用的に転用可能な形」に整える(法令対応)

## 法令・規約への二重チェック
- 有料記事は note 規約の "情報商材的扱い" を受けやすい
- 「絶対勝てる」「秘密の手法」のような **誇大広告ワードは完全禁止**
- 個別銘柄・通貨ペアの **目標価格・売買タイミング指示は禁止**(無料記事と同等)

## 出力フォーマットの追加
- 通常のテンプレに加えて、本文中の有料境界を:
  ```
  <!-- PAYWALL -->
  ```
  という HTML コメントで 1 箇所マークする(note で手動配置する目印)
