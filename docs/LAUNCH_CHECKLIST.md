## 🛡 安全装置(本システムに組み込み済み)

このスケジュールは「**A8 提携承認が遅れても稼働を止めない**」設計です。

| 状況 | システムの動作 |
|---|---|
| Day 1-7: A8 全件未承認(`YOUR_A8_xxx` のまま) | プレースホルダリンクを自動スキップ → Amazon 書籍リンク(最大 2 件)で代替 |
| Day 8-10: A8 一部承認 | 承認分のみ A8 で挿入、未承認分は Amazon フォールバック |
| Day 10+: A8 全承認 | 通常モード(A8 × 3 + Amazon × 1) |

→ Day 2 試運転で **壊れたリンクが入る心配は無し**。A8 承認状況にかかわらず Day 2 から本稼働可能。

# 🚨 2 週間ローンチで起こりやすい詰まり TOP 6

| 詰まり | 起こる日 | 対処 |
|---|---|---|
| **A8 承認が Day 7 時点で 4 件以下** | Day 5-7 | Day 8 反映を後ろ倒し、Day 8-10 も慣らし継続。Amazon フォールバックで稼働は継続 |
| **X Access Token が Read only** | Day 1-2 | App permissions を Read+Write に変更後、必ず **Token を再発行** |
| **ドラフト workflow が失敗** | Day 2 | Anthropic クレジット切れ / Secret 名ミスが大半。Actions タブの log で確認 |
| **Issue にコメントしても X 投稿されない** | Day 2 | コメント形式 `note: https://...` の半角コロン+スペース必須 |
| **1日10本がキツい(Day 12)** | Day 11-12 | 無理せず 6-8 本/日で OK、慣らし優先。本数より継続 |
| **note の有料設定がわからない** | Day 9 | note 編集画面の「価格を設定」ボタン → ¥100 → 「ここから先は有料です」境界をドラッグで設定 |

# 🆘 緊急時連絡

- **GitHub Actions が止まった**: Actions タブの該当 workflow log を確認 → エラー文を Issue に貼って質問
- **X が突然投稿できなくなった**: Free tier の月 500 投稿上限到達確認 → 翌月まで cron を半減
- **Claude API のコストが急騰**: cost_guard.py が自動停止する設計だが、Variables の `DAILY_COST_LIMIT_USD` を一時的に下げて様子見
